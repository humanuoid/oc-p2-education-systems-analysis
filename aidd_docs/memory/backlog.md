# Backlog

## Supports

| Support | Authority for | Role |
| --- | --- | --- |
| Issues GitHub | travail à faire, consignes de l'énoncé OC | source des tâches PHx.y-nn |
| Projet Kanban GitHub | statut des tâches | suivi au fil de l'eau |

## Nomenclature

- Titre d'issue : « PHx.y-nn · <verbe> <objet> », nn zéro-paddé
- Le tri alphabétique du titre donne l'ordre d'exécution dans le Kanban
- Labels : `phase-N` + un label thématique
- Note : l'énoncé OC appelle « partie 1 » ce que le Kanban numérote « partie 2 » (protocole qualité) ; ne plus utiliser le numéro de l'énoncé

## Workflow

- Statut des issues et du Kanban mis à jour au fil de l'eau, à chaque avancée

## Règles de travail sur les issues

- Attendre les consignes avant d'exécuter : livrer ce qui est demandé, puis attendre ; ne pas choisir la sélection finale ni ajouter des livrables de son propre chef
- Si l'analyse semble mauvaise, en discuter avec l'utilisateur plutôt que corriger de son côté
- Critères d'acceptation au plus près de l'énoncé + strict nécessaire : pas de contrôles formels inventés par l'IA
- Pas de suringénierie : ne rien faire au-delà de ce qui est demandé
